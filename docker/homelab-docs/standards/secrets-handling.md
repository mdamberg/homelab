# Secrets Handling

## Approach

All secrets are managed through a single master `.env` file at `docker/.env`. A script deploys the right variables to each service folder. This means:

- One place to edit secrets
- No risk of per-service files falling out of sync
- Per-service `.env` files are disposable — regenerate them any time with `setup-env.ps1`

---

## Workflow

### Fresh clone or missing .env files

```powershell
# 1. Copy the template
cp docker/.env.example docker/.env

# 2. Fill in real values (see "Where to find secrets" below)
notepad docker/.env

# 3. Deploy to all service folders
cd docker
.\setup-env.ps1
```

### Updating a secret

```powershell
# 1. Edit the master file
notepad docker/.env

# 2. Re-deploy
cd docker
.\setup-env.ps1

# 3. Restart affected service
cd docker/docker-projects/<service>
docker compose up -d
```

### Recovering secrets from running containers

If you need to recover a secret from a container that's still running:

```powershell
docker inspect <container_name> --format '{{range .Config.Env}}{{println .}}{{end}}'
```

## File Structure

```
docker/
├── .env              # Master secrets file — gitignored, never committed
├── .env.example      # Template with all variable names — committed, no real values
├── setup-env.ps1     # Deploys master .env to all service folders
└── docker-projects/
    ├── media_stack/.env     # Generated by setup-env.ps1
    ├── backups/.env         # Generated by setup-env.ps1
    ├── n8n/.env             # Generated by setup-env.ps1
    └── ...                  # All other service .env files
```

## Where Secrets Live by Service

| Service | Variables in master .env |
|---------|--------------------------|
| Media Stack (Gluetun/PIA) | `OPENVPN_USER`, `OPENVPN_PASSWORD`, `HOMARR_SECRET_KEY` |
| Backups (Duplicati) | `DUPLICATI_WEBPASS`, `HEALTHCHECKS_URL`, `SETTINGS_ENCRYPTION_KEY` |
| Lightdash | `LIGHTDASH_PG_USER`, `LIGHTDASH_PG_PASSWORD`, `LIGHTDASH_SECRET`, `MINIO_*`, `S3_*` |
| Linkding | `LD_SUPERUSER_NAME`, `LD_SUPERUSER_PASSWORD` |
| phpIPAM | `IPAM_DATABASE_NAME`, `MYSQL_USER`, `MYSQL_PASSWORD`, `MYSQL_ROOT_PASSWORD` |
| n8n | `TELLER_APPLICATION_ID`, `TELLER_CERTS_HOST_PATH`, `TELLER_TOKENS` |
| MCP Server | `N8N_API_KEY`, `N8N_API_URL` |
| Weather | `WEATHER_API_KEY` |
| Shared | `TZ`, `PUID`, `PGID` |

## Rules

**Never commit `docker/.env`.** It is gitignored. If it accidentally gets committed, rotate the affected credentials immediately.

**Never put real values in `.env.example`.** That file is committed — it is a template only.

**Never hardcode secrets in `docker-compose.yml`.** Always reference them via `${VAR}` from `.env`.

---

## Backup of Secrets

The master `docker/.env` is included in the Duplicati backup (Docker configs backup source covers the full `docker/` directory). Backups are encrypted.

On a full restore: restore the Duplicati backup first, then `setup-env.ps1` will regenerate all per-service `.env` files.

---

## Future Improvements

- Consider moving to Docker secrets or a secrets manager (e.g., Infisical, Vault) for more sensitive credentials
- Enable 2FA on any service that supports it
- Audit `.env` periodically to rotate old or default passwords
